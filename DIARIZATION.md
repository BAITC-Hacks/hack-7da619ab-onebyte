# Локальная диаризация Meeting AI

Транскрибация по-прежнему выполняется faster-whisper (`small`, CPU, `int8`).
Pyannote Community-1 запускается **после Whisper в отдельном процессе** на CPU.
Если модель или библиотека недоступна, процесс заблокирован Windows, завершился
аварийно или превысил время ожидания, сервер возвращает обычный транскрипт и
сообщение «Диаризация недоступна в текущей среде». Windows Security не изменяется.

## Подготовка модели один раз

1. Примите условия доступа к модели на странице
   https://huggingface.co/pyannote/speaker-diarization-community-1.
2. Установите зависимости в выбранное Python-окружение (Python 3.10+).
   В существующем окружении проекта:

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

   Если у текущего окружения рабочая конфигурация Whisper, сначала сохраните его
   зависимости или установите pyannote в отдельное окружение. Для отдельного
   окружения нужны `pyannote.audio>=4.0.1,<5`, `huggingface-hub>=0.28,<2` и
   `faster-whisper` (для локального декодирования MP3/WAV/M4A).
3. Авторизуйтесь в Hugging Face без сохранения токена в исходниках:

   ```powershell
   .\.venv\Scripts\hf.exe auth login
   .\.venv\Scripts\python.exe diarization.py --download-model
   ```

   Вместо `hf auth login` можно передать `HF_TOKEN` через окружение процесса.
   Не вставляйте токен в Python-файлы, команды с литералом токена, Git или логи.
   Команда скачивает весь репозиторий модели, включая segmentation, embedding
   и PLDA. Аудио ей не передаётся. При отказе Hugging Face обычная транскрибация
   остаётся работоспособной.

4. Запустите приложение:

   ```powershell
   .\.venv\Scripts\python.exe app.py
   ```

   Откройте http://127.0.0.1:8000 и загрузите запись.

При обработке модель берётся только из локального Hugging Face cache.
Автоматического скачивания во время загрузки аудио нет. Worker использует
`HF_HUB_OFFLINE=1`, `HF_HUB_DISABLE_TELEMETRY=1`,
`PYANNOTE_METRICS_ENABLED=0`, `OTEL_SDK_DISABLED=true`; токен worker не получает.
Модель загружается из локального пути с `token=False`. Обработка аудио не вызывает
внешние API. WAV/MP3/M4A декодируются локально PyAV через faster-whisper, затем
pyannote получает waveform 16 кГц, а не путь для собственного декодера.

## Настройки PowerShell

Установите переменные перед запуском приложения; они не меняют системные политики.

```powershell
# Необязательно: полный локальный каталог Community-1 с config.yaml и весами.
$env:DIARIZATION_MODEL_PATH = 'D:\models\speaker-diarization-community-1'

# Необязательно: Python отдельного окружения с pyannote и faster-whisper.
$env:DIARIZATION_PYTHON = 'D:\envs\diarization\Scripts\python.exe'

# По умолчанию 180 секунд на запуск, загрузку модели и обработку.
# Для длинных записей на CPU лимит можно увеличить.
$env:DIARIZATION_TIMEOUT_SECONDS = '600'

# Для быстрого запуска только Whisper (по умолчанию диаризация включена).
$env:DIARIZATION_ENABLED = '0'
```

Указывайте только существующие пути. Чтобы вернуться к стандартному кэшу,
удалите переменную `DIARIZATION_MODEL_PATH` из текущей PowerShell-сессии.
После изменения настроек перезапустите сервер. Модель загружается заново для
каждой записи: это намеренный компромисс ради изоляции сбоев нативных библиотек.
Одновременно работает один worker; второй запрос получает обычный транскрипт.

## Контракт API и будущая связь с поручениями

`POST /api/transcribe` сохраняет прежнее поле `transcript` и добавляет:

```json
{
  "transcript": "Подготовьте отчёт.",
  "segments": [
    {"id": 0, "speaker": "SPEAKER_00", "start": 0.5, "end": 4.2, "text": "Подготовьте отчёт."}
  ],
  "diarization": {"status": "available", "message": "Говорящие определены локально..."}
}
```

Начало/конец — секунды исходного аудио из Whisper. Используется
`exclusive_speaker_diarization` Community-1. Для каждого сегмента суммируется
пересечение с интервалами каждого говорящего; побеждает максимальное. При
равенстве выбирается первый появившийся говорящий. Пересекающиеся интервалы
одного говорящего объединяются перед подсчётом. При отсутствии пересечения
`speaker: null` и интерфейс показывает «Говорящий не определён».

При fallback все исходные сегменты сохраняются с `speaker: null`, а
`diarization.status = "unavailable"`. `reason` — безопасный диагностический код:
`model_not_cached`, `import_unavailable`, `model_unavailable`, `inference_failed`,
`worker_failed`, `timeout`, `disabled`, `busy` или `unexpected_failure`.
Пустая запись даёт `status: "no_speech"`. Никаких выдуманных SPEAKER_00 при fallback.

Идентификаторы сегментов и говорящих действуют только внутри одной записи.
Будущие поручения могут ссылаться на `segments[].id` как `source_segment_ids`
и хранить `source_speaker`. Говорящий, произнёсший поручение, **не обязательно
его ответственный**: автоматически заменять ответственного на speaker нельзя.
Текущие анализ и DOCX продолжают использовать исходный текст без speaker-разметки.
Сегмент с несколькими голосами получает один доминирующий speaker; это не
пословная разметка и не установление личности человека.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest test_speaker_diarization test_meeting_ai -v
```

Тесты проверяют пересечения, неизвестных говорящих, ошибки импорта/модели,
падение worker, таймаут, очистку временных файлов и сохранность Whisper.
`test_diarization.py` пользователя не изменяется и автоматически не запускается.
Если Windows блокирует `.pyd`, используйте fallback либо совместимое разрешённое
окружение. Эта реализация не отключает защиту и не обходит блокировки Windows.
